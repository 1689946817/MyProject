# 毕设期间记事与答疑记录

## 记录1

**每周工作记事**  
本周围绕毕业设计选题进一步查阅多模态检索、多模态大模型与 RAG 相关文献，重点比较了 CLIP 一类统一跨模态向量方法与“图像先转语义描述、再走文本检索链路”的方案差异。同时结合现有开发条件，初步梳理后端、向量库和前端交互的技术选型范围。

**问题简述**  
在毕设周期和个人开发能力有限的前提下，系统主线应优先采用统一跨模态向量空间方案，还是采用“语义描述桥接”的技术路线，才能同时兼顾研究价值与工程可实现性。

**教师回答**  
现阶段应优先选择“语义描述桥接”路线。统一跨模态向量空间虽然理论上更直接，但对模型能力、数据分布和对齐质量要求较高，且调参与评估成本大，不利于本科毕业设计在限定周期内形成完整闭环。相对而言，先利用多模态模型生成结构化文本描述，再复用成熟文本检索和 RAG 流程，更容易落地，也更适合在论文中清晰说明系统分层、数据流和实验对比逻辑。后续可将跨模态向量方法作为基线或对比对象，而不必作为主实现路线。

**问题简述**

**教师回答**

## <u>记录3</u>

**每周工作记事**  
本周围绕图像描述生成模块整理了提示词设计思路，尝试从“主体对象、属性特征、空间关系、场景语义”等维度定义输出结构，并记录了不同提示风格可能对检索效果带来的影响。

**问题简述**  
图像描述文本如果写得过短，可能无法覆盖细粒度语义；如果写得过长，又可能引入噪声并增加向量检索与 RAG 上下文负担。描述粒度应如何控制，才能兼顾检索有效性与后续问答可用性。

**教师回答**  
描述文本不应追求“越详细越好”，而应服务于检索与问答两个任务。建议采用模板化、多句式、要素覆盖型描述，让文本稳定覆盖主体、属性、空间关系和关键语义，但避免无关修辞与重复信息。你可以把“信息覆盖度、语义一致性、可检索性”作为描述质量的核心标准，并在论文中说明这种粒度控制属于系统设计的一部分，而不是单纯依赖模型自由生成。

**问题简述**

**问题简述**  
在数据建模阶段，图像元数据、生成描述、向量索引标识和后续检索引用信息之间应如何保持一致，才能避免后面出现“数据库记录存在但向量库找不到”或“检索结果无法回溯原图”的问题。

**教师回答**  
应从一开始就以统一主键贯穿全链路。每张图像在文件存储、关系型数据库和向量库中都应使用同一资源 ID，并同步保存必要的回溯 metadata，例如文件路径、标题、来源和状态。后续检索结果返回时，不仅要返回相似度，还要能基于该 ID 找回原始资源和相关说明。你可以把这一点上升为“三存储一致性”的设计原则，这也是系统工程层面的关键问题。

**问题简述**

## <u>记录12</u>

**每周工作记事**  
本周着手设计 RAG 问答模块，开始思考如何将检索得到的图像描述、文档片段及必要的原始资源信息一起组织进提示词，并控制上下文长度。

**问题简述**  
多模态 RAG 问答中，检索结果不宜全部无差别拼接进上下文，但如果压缩过度又可能丢失关键信息。当前阶段应如何平衡上下文充分性与提示长度。

**教师回答**  
建议优先建立“候选召回 - 筛选 - 组织”的分层策略，而不是把更多内容机械堆进去。你可以限定 Top-K 数量，并按照资源类型、相似度和信息完整度挑选上下文，再为每条结果保留必要的来源信息。系统当前阶段更重要的是形成稳定、可解释的问答流程，而不是追求单次回答中包含尽可能多的材料。后续若时间允许，再考虑加入上下文压缩或重排序优化。
