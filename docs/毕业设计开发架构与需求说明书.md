

# 🎓 毕业设计开发架构与需求说明书 (Cursor Dev Prompt)

## 1. 项目概述 (Project Overview)

**项目名称**：基于多模态大模型与双路检索的多模态RAG知识库系统 **核心思想**：摒弃复杂的跨模态向量对齐，利用多模态大模型（MLLM）的强大语义理解能力，将图像“翻译”成结构化的详细文本描述 。从而将复杂的多模态检索转化为成熟的单文本检索，并支持“文本→图像”与“图像→图像”的双路检索以及基于检索增强（RAG）的多模态智能问答 。

## 2. 技术栈规范 (Tech Stack Requirements)

请 AI 助手在生成代码时，严格遵循以下技术栈选型 ：

* **后端框架 (Backend)**: Python 3.10+ 配合 `FastAPI` 框架。
* **前端框架 (Frontend)**: `Vue.js` (推荐 Vue 3 + TypeScript + Vite) 或 `React`。UI组件库可选用 Element Plus 或 Tailwind CSS。
* **向量数据库 (Vector DB)**: `ChromaDB` 。
* **关系型数据库 (Relational DB)**: 轻量级 `SQLite` (用于存储图像元数据、映射关系及历史会话)。
* **AI 接口集成 (AI Integration)**:
* *多模态模型 (图像描述/VQA)*: 支持接入 `Qwen-VL`、`LLaVA` 或 `BLIP-2` 兼容接口（可通过 OpenAI API 格式）。
* *嵌入模型 (Embedding)*: `BGE-m3` (BAAI General Embedding) 或 `text2vec`。
* *生成模型 (LLM)*: 任意支持上下文对话的大语言模型接口。



## 3. 系统分层架构 (System Architecture)

系统遵循严格的**五层架构**，开发目录需按照此逻辑解耦 ：

1. **数据层 (Data Layer)**:
* 负责图片本地/云端存储 (`/storage/images`)。
* 使用关系型数据库管理图像ID与文本描述的映射关系及系统业务数据。


2. **语义化层 (Semantic Layer)**:
* 封装 MLLM 调用接口，将上传的图像转化为覆盖主体、属性、空间关系的高质量“结构化文本描述”。
* 包含描述质量控制逻辑（模板约束与提示词工程）。


3. **检索层 (Retrieval Layer)**:
* 集成 Embedding 模型，将文本向量化。
* 操作 ChromaDB/Milvus 实现向量索引、近邻搜索，并设计基于相似度得分的重排序 (Re-ranking) 逻辑。


4. **应用层 (Application Layer)**:
* **双路检索调度器**: 统一处理文本输入 (直接向量化) 和图像输入 (先调语义化层转文本，再向量化) 的查询。
* **RAG 引擎**: 组装检索结果（图像结构化描述片段 + 原图信息）与用户Query，构建多模态 Prompt 进行问答生成。


5. **展示层 (Presentation Layer)**:
* Web 前端界面：包含搜索框、图片上传组件、图像瀑布流/网格展示区、RAG 聊天对话框。



## 4. 核心数据模型 (Data Models Schema)

后端需使用 ORM（如 SQLAlchemy）定义以下核心表结构：

* **ImageRecord (图像元数据表)**:
* `id`: UUID (Primary Key)
* `file_path`: String (本地路径或URL)
* `upload_time`: DateTime
* `generated_description`: Text (多模态大模型生成的结构化文本描述)
* `status`: String (Processing, Completed, Failed)


* **VectorStore (向量库 - 逻辑定义)**:
* `id`: String (对应 ImageRecord 的 ID)
* `embedding`: Vector (文本描述的向量表示)
* `metadata`: JSON (包含图像基础信息以便快速过滤)



## 5. API 接口规范 (API Specification)

后端需提供以下 RESTful 接口供前端调用：

1. `POST /api/knowledge-base/upload`
* *功能*: 上传单张/多张图片，触发语义化层生成描述并存入关系型数据库和向量库。


2. `POST /api/search/text-to-image`
* *功能*: 接收文本 Query，返回相关图像列表及相似度分数。


3. `POST /api/search/image-to-image`
* *功能*: 接收图片，调用 MLLM 转文本后，返回相似图像列表。


4. `POST /api/rag/chat`
* *功能*: 接收用户问题（文本/图片），执行检索后，利用 RAG 机制生成专业回答（支持流式输出 Streaming）。



## 6. Cursor 开发分步实施指令 (Step-by-Step Prompting)

*建议在 Cursor 中分发以下指令来进行渐进式开发：*

* **Step 1: 初始化与基础设施搭建**
> "请使用 FastAPI 和 SQLAlchemy 初始化后端项目，配置 SQLite/PostgreSQL 数据库连接。同时使用 Vue 3 + Vite 初始化前端项目。建立前后端跨域通信 (CORS)。"


* **Step 2: 构建数据层与语义化层**
> "在后端创建 `ImageRecord` 数据库模型，并实现图片上传的 API。集成 OpenAI API 格式的调用方法（我们将用于对接 Qwen-VL/LLaVA），当图片上传后，编写提示词让模型生成结构化的图像描述（包含主体、颜色、空间关系），并存入数据库。"


* **Step 3: 检索层与向量库集成**
> "引入 `chromadb` 和对应的 Embedding 模型（如 HuggingFace BGE）。编写逻辑：当图像描述生成后，将其向量化并存入 ChromaDB，建立 ID 映射。实现文本查询接口，在 ChromaDB 中执行近邻搜索并返回原图片路径。"


* **Step 4: 双路检索调度与 RAG 引擎**
> "实现业务逻辑层的调度器：如果收到图片搜索请求，先复用 Step 2 的逻辑生成描述，再复用 Step 3 的检索逻辑，实现以图搜图。接着实现 RAG 对话接口，将检索到的前 Top-K 个图像描述和用户的问题组装成 Prompt，交给 LLM 生成回答。"


* **Step 5: 前端展示层**
> "在 Vue 前端开发三个核心组件：1. 知识库管理（支持图片上传和列表展示）。 2. 检索面板（支持文本/图片上传搜索，展示网格状结果）。3. 智能问答侧边栏（类 ChatGPT 聊天界面，支持展示 RAG 回答中引用的图片）。"
