# 多模态 RAG 知识库系统 — 实验部分详细总结

## 1. 实验设计概述

本项目包含两个独立的实验模块：

- **检索器评估**：在 MS-COCO 子集上对比不同检索方法的 Recall@K / MRR / mAP
- **生成器评估**：使用 LLM-as-a-Judge 方法评估 RAG 系统的生成答案质量

两个模块通过 JSON 文件解耦：检索器评估直接输出指标，生成器评估先由 `run_gen_*.py` 生成答案 JSON，再由评估器打分。

---

## 2. 检索器评估

### 2.1 评估入口

```bash
python -m evaluation.run_offline_eval \
  --dataset-path data/coco_subset_eval.json \
  --method proposed \
  --top-k 10
```

### 2.2 参与对比的方法

| 方法名 | 核心思路 | 实现文件 |
|--------|---------|---------|
| `proposed` | MLLM 生成结构化描述 → 文本向量检索 | `methods/proposed_multimodal_rag.py` |
| `baseline_clip` | 多模态 embedding（qwen3-vl-embedding）直接编码图片 → 跨模态检索 | `methods/baseline_clip_retrieval.py` |
| `baseline_ocr` | OCR 提取图片文字 → 文字向量检索 | `methods/baseline_ocr_rag.py` |

> `baseline_text_rag.py` 保留在 `methods/` 目录中但不参与当前实验。

### 2.3 评估数据集格式

文件路径：`data/coco_subset_eval.json`（需自行准备）

```json
[
  {
    "query": "a dog running on the beach",
    "relevant_ids": ["uuid-1", "uuid-2"],
    "reference_answer": "A dog is running on the beach."
  }
]
```

`relevant_ids` 必须与知识库中图像的 UUID 对应。

### 2.4 评估指标

| 指标 | 说明 |
|------|------|
| Recall@K（K=1,5,10） | 前 K 个结果中命中相关图像的比例 |
| MRR | 第一个相关结果排名的倒数均值 |
| mAP@K | 综合考虑排序质量的平均精度均值 |

实现文件：`evaluation/metrics.py`

## 3. 生成器评估

### 3.1 两组实验

#### 第一组：纯图片知识库

知识库只包含图片，无文档文本。

```bash
python -m evaluation.run_gen_image_only \
  --dataset-path data/coco_subset_eval.json \
  --method proposed \
  --top-k 5 \
  --output-dir data/rag_outputs/image_only_kb
```

支持的方法（共 6 个）：

| 方法名 | 检索来源 | 传给 LLM 的内容 |
|--------|---------|----------------|
| `proposed` | 图片语义描述向量库 | 原始图片（base64）|
| `baseline_clip` | 多模态 embedding 向量库 | 原始图片（base64）|
| `baseline_ocr` | OCR 文字向量库 | 原始图片（base64）|
| `text_summary_rag` | 图片语义描述向量库 | 图片描述文字（不传图片）|
| `ocr_text_rag` | OCR 文字向量库 | OCR 识别文字（不传图片）|
| `no_rag` | 不检索 | 只有问题本身 |

#### 第二组：多模态文档知识库

知识库为 PDF/Word/Markdown 等多模态文档（含文本、图片、表格）。在图片检索基础上额外检索文本段落作为补充上下文。

> 注：文档解析部分待后续实现，`_get_text_context()` 中标有 TODO。

```bash
python -m evaluation.run_gen_multimodal \
  --dataset-path data/coco_subset_eval.json \
  --method proposed \
  --top-k 5 \
  --output-dir data/rag_outputs/multimodal_kb
```

支持的方法（共 7 个，在第一组基础上新增 `text_kb_rag`）：

| 方法名 | 检索来源 | 传给 LLM 的内容 |
|--------|---------|----------------|
| `proposed` | 图片语义描述 + 文档文本 | 原始图片 + 文档段落 |
| `baseline_clip` | 多模态 embedding + 文档文本 | 原始图片 + 文档段落 |
| `baseline_ocr` | OCR 文字 + 文档文本 | 原始图片 + 文档段落 |
| `text_summary_rag` | 图片语义描述 + 文档文本 | 图片描述文字 + 文档段落 |
| `ocr_text_rag` | OCR 文字 + 文档文本 | OCR 文字 + 文档段落 |
| `text_kb_rag` | 仅文档文本（忽略图片） | 文档段落 |
| `no_rag` | 不检索 | 只有问题本身 |

### 3.2 输出格式

每个方法输出一个 JSON 文件，路径为 `data/rag_outputs/{实验组}/rag_output_{method}.json`：

```json
[
  {
    "user_query": "...",
    "reference_answer": "...",
    "generated_answer": "...",
    "context": "...",
    "image": ["base64..."]
  }
]
```

### 3.3 生成质量评估指标（LLM-as-a-Judge）

评估器位于 `evaluation/evaluators/`，支持 GPT-4V（Azure）和 LLaVA 两种 judge 模型。

| 指标 | 说明 | 所需输入 |
|------|------|---------|
| Answer Correctness | 答案与参考答案的一致性 | query, generated, reference |
| Answer Relevancy | 答案与问题的相关性 | query, generated |
| Image Faithfulness | 答案与检索图像的事实一致性 | generated, image |
| Text Faithfulness | 答案与检索文本的事实一致性 | generated, context |
| Image Context Relevancy | 检索图像与问题的相关性 | query, image |
| Text Context Relevancy | 检索文本与问题的相关性 | query, context |

## 4. 评估模块文件结构

```
evaluation/
├── __init__.py
├── metrics.py                      # Recall@K / MRR / mAP 计算
├── run_offline_eval.py             # 检索器评估入口
├── run_gen_image_only.py           # 生成器评估入口 — 第一组：纯图片知识库
├── run_gen_multimodal.py           # 生成器评估入口 — 第二组：多模态文档知识库
├── _generation_core.py             # 两组实验共用的公共逻辑
├── datasets/
│   ├── __init__.py
│   └── coco_subset.py              # 数据集加载（CocoQuerySample）
├── evaluators/                     # LLM-as-a-Judge 评估器
│   ├── __init__.py
│   ├── evaluator_interface.py      # 抽象接口
│   ├── base_evaluator.py           # 基础评估器（LangChain 链式调用）
│   ├── evaluators_openai.py        # GPT-4V 评估器实现
│   └── evaluators_llava.py         # LLaVA 评估器实现
└── methods/                        # 检索 / 生成方法
    ├── __init__.py
    ├── proposed_multimodal_rag.py  # 检索+生成：语义描述检索 → 传图片
    ├── baseline_clip_retrieval.py  # 检索+生成：多模态 embedding → 传图片
    ├── baseline_ocr_rag.py         # 检索+生成：OCR 检索 → 传图片
    ├── text_summary_rag.py         # 仅生成：语义描述检索 → 传描述文字
    ├── ocr_text_rag.py             # 仅生成：OCR 检索 → 传 OCR 文字
    ├── no_rag.py                   # 仅生成：不检索，直接问 MLLM
    └── baseline_text_rag.py        # 保留备用，不参与当前实验
```

## 5. Embedding 模型配置

| 用途 | 模型 | 配置项 |
|------|------|--------|
| 主流程文本向量检索 | `text-embedding-v4` | `EMBEDDING_MODEL_NAME` |
| CLIP baseline 图文同空间编码 | `qwen3-vl-embedding` | `MULTIMODAL_EMBEDDING_MODEL_NAME` |

## 6. 实验前置条件

运行各方法前需先构建对应的向量索引：

| 方法 | 需要的索引 | 构建方式 |
|------|-----------|---------|
| `proposed` / `text_summary_rag` | `images_semantic_desc` | 通过后端上传图片接口自动构建 |
| `baseline_ocr` / `ocr_text_rag` | `images_ocr_text` | 调用 `baseline_ocr_rag.build_ocr_index()` |
| `baseline_clip` | `images_multimodal_embedding` | 调用 `baseline_clip_retrieval.build_vector_index()` |
